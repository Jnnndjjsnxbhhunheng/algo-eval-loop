# 评估标准文档编写指南

## eval-criteria.md 格式规范

评估标准文档是整个迭代工作流的核心驱动文件。产品用它指导评估，算法用它理解要优化的方向。

## 文档结构

```markdown
# [项目名称] 评估标准

## 元信息
- 当前版本：v1.2
- 最后更新：2025-01-15
- 生效起始版本：v3（即从算法 v3 开始按此标准评估）

## 评估维度

### 维度 1：[维度名称]
- **定义**：这个维度衡量什么
- **评分区间**：1-5 / 0-10 / 通过/不通过
- **评分标准**：
  - 5分：[具体描述什么情况给5分]
  - 4分：[具体描述]
  - 3分：[具体描述]
  - 2分：[具体描述]
  - 1分：[具体描述]
- **权重**：（可选）该维度在总分中的占比

### 维度 2：[维度名称]
...

## 变更记录
| 日期 | 变更内容 | 原因 | 生效版本 |
|------|---------|------|---------|
| 2025-01-15 | 新增"品牌匹配度"维度 | 业务新增品牌筛选需求 | v3 |
| 2025-01-01 | 初始版本 | 项目启动 | v1 |
```

## 编写原则

**可打分**：每个维度必须有明确的评分标准，不能是模糊的"好不好"。产品同学看到标准后，不同人给同一条数据打出的分数差异应该不超过 1 分。

**可关联**：维度命名和定义要能关联到算法代码中的具体逻辑。比如"排序合理性"可以关联到排序算法的打分函数，"覆盖率"可以关联到召回逻辑。这样分析反馈时能快速定位代码。

**可演化**：变更记录要清晰，新的评估人来了之后能看懂为什么有这些维度、历史上做过什么调整。

## 常见评估维度模板

以下是一些常见场景的评估维度参考（按需选用，不是都要有）：

### 搜索/推荐/排序类
- 准确性：结果是否正确、是否答非所问
- 相关性：与查询意图的匹配程度
- 排序合理性：排在前面的是否确实比后面的好
- 覆盖率：应该出现的结果是否都出现了
- 多样性：结果是否过于同质化

### 生成/提取类
- 完整性：是否提取/生成了所有需要的信息
- 准确性：提取/生成的信息是否正确
- 格式规范性：输出是否符合预期格式
- 一致性：相似输入是否产出相似结果

### 分类/标注类
- 准确率：分类是否正确
- 边界处理：模棱两可的 case 处理是否合理
- 覆盖率：是否有遗漏未分类的数据

## 评估标准与 Excel 的映射

在生成给产品的 Excel 时，每个评估维度对应一个列：

| 列名格式 | 说明 |
|----------|------|
| `[维度名称]_评分` | 数值评分列，如 `准确性_评分` |
| `[维度名称]_备注` | 文字说明列，用于产品标注具体问题 |

Excel 第一行固定为表头，第二行写评分说明（从标准文档提取），从第三行开始是数据。
